How I Built a Car Recommendation
& Pricing System with Machine Learning

A walkthrough of my Final Year Project at UniSZA: the problem it solves, how the hybrid recommender and Random Forest price model fit together, and what I learned building it.

TL;DR

For my Final Year Project I built a web-based system that recommends suitable cars to buyers and estimates a fair market price. It combines a hybrid recommender (content-based + collaborative filtering) with a Random Forest price prediction model, wrapped in a PHP and MySQL web application with modules for buyers, sellers and administrators.

Buying a car, new or used, is one of the biggest purchases most people make. Yet the process is often confusing: there are hundreds of models to compare, and it is hard to know whether a listed price is actually fair. Sellers face the opposite problem, struggling to decide what price to ask.

I wanted my Final Year Project to tackle both sides of that problem with data. The result is the Intelligent Car Recommendation and Pricing System Using Machine Learning. In this post I'll walk through how it works and what I learned along the way.

01 The Problem I Wanted to Solve

The system was designed around three groups of users, each with a different need:

  • Buyers want to find cars that match their preferences and budget without browsing endless listings.
  • Sellers want a reasonable price estimate before listing their vehicle.
  • Administrators need to manage users, listings and transactions in one place.

The goal was to support better decisions on both sides of a car sale through data-driven recommendations and automated price predictions.

02 System Architecture

The system has two main parts: a PHP web application that users interact with, and a Python layer that runs the machine learning models. MySQL stores everything in between.

03 The Hybrid Recommender

Recommendation systems usually follow one of two approaches, and each has a weakness on its own:

  • Content-based filtering recommends cars similar to what a user is looking for, based on attributes like brand, body type, price range and fuel type. It works even for new users, but tends to suggest very similar options.
  • Collaborative filtering recommends cars that users with similar behaviour liked. It can surface less obvious choices, but struggles when there is little interaction data (the "cold start" problem).

Why hybrid?

Combining both approaches lets each one cover the other's weakness. Content-based filtering gives reasonable suggestions from the start, while collaborative filtering adds variety as more users interact with the system.

04 Predicting Prices with Random Forest

For pricing, I used a Random Forest regression model. A Random Forest trains many decision trees on different samples of the data and averages their predictions. This makes it more stable than a single tree and good at capturing non-linear relationships, such as how a car's value drops with age and mileage at different rates for different brands. Here is a simplified example of the idea:

05 Key Lessons & Takeaways

Data quality matters more than the algorithm

Cleaning and preparing the data took a large share of the effort. A good model cannot make up for messy or inconsistent input.

Integration is its own challenge

Connecting a PHP web application to Python models taught me a lot about passing data between components cleanly.

Plan the documentation alongside the code

An FYP is judged on the report as well as the system. Writing chapters as I built each part kept the two consistent.

Design for every type of user

Building separate modules for buyers, sellers and administrators forced me to think through each user's workflow and permissions carefully.
